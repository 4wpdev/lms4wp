# 0010. IDE-практика уроку — з даних чаптера (`ide.json`)
Дата: 2026-11-15 · Статус: Прийнято

## Контекст
Практика «напиши код» (CRUD, хуки, шлюз оплати, блоки) у терміналі не робиться: термінал — для CLI-дій.
IDE-блок 4wp-advanced-code уже має редактор, кроки Back/Next і кнопку Check, але дані бере лише з каталогу хуків теми,
а Check знає три правила (функція, хук, `return`).

## Рішення
1. Як у ADR 0006: у модулі хабу — один `ide.json`, ключ `lessons.<файл уроку без .md>.tasks`. Імпорт кладе його в мета модуля `_lms4wp_ide`; `verify` звіряє.
2. В уроці — лише тег практики: порожній ```` ```ide ```` → блок `lms4wp/lesson-ide` → `forwp-advanced-code/ide` з атрибутом `practice: lms4wp-lesson-<ID>`.
3. 4wp-advanced-code: універсальний фільтр `forwp_ac_ide_practice_data` і REST `/ide/practice/<profile>`; про LMS не знає. Задачі перетворюються на ті самі wizard-кроки (`read`, `example`, `practice`, `quiz`, `done`).
4. Check — статичні правила без виконання PHP (ADR 0009, п. 3): `function`, `hook`, `returns` + `must` / `must_not` (`text` — підрядок, `regex` — вираз; коментарі в коді ігноруються), `hint` на кожне правило, `success` — повідомлення про успіх.
5. Виконання коду (php-wasm / Playground) — не зараз; на сервері — ніколи.

## Наслідки
- Без LMS4WP IDE працює як раніше (каталог хуків).
- Профіль віддається публічним REST лише для опублікованих уроків (або тим, хто може їх читати).
- Один файл на задачу; кілька задач уроку — кілька «вкладок» по черзі (Next task).
