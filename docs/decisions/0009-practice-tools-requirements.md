# 0009. Практичні інструменти уроків: вимоги
Дата: 2026-11-15 · Статус: Прийнято

## Контекст
Практика в уроках — симулятори: термінал (`terminal.json` чаптера, ADR 0006), надалі IDE та подібні.
Перші профілі віддавали заготовлені відповіді, які не залежали від введення: `git commit -m` без повідомлення
«комітив» з чужим текстом, `git switch -c` без імені створював гілку, невідома команда — `Error: not a registered command`.
Для учня це виглядає як зламаний інструмент і підриває довіру до курсу.

## Рішення
Кожен практичний інструмент (термінал, IDE, будь-який симулятор) відповідає таким вимогам.

1. **Реалістичність.** Відповідь — така, яку дав би справжній інструмент у цій ситуації: реальні формати виводу,
   реальні помилки (команда без обов'язкового аргументу → справжня помилка git, а не «успіх»).
2. **Стан.** Результат залежить від дій учня (state + variants): `status`, `diff`, `log` показують те, що він зробив;
   введені значення (повідомлення коміту, текст) використовуються у виводі.
3. **Фіксований сценарій, мінімум команд.** Один сценарій на чаптер з фіксованими іменами (файли, гілки),
   лише стандартні команди уроків. Межі сценарію — чесні: «у цьому сценарії …», а не імітація.
   Жодних «повних симуляцій» (state machine, BFS) — дорого і непідтримувано.
4. **Непокриті команди — межа сценарію, не помилка.** Три рівні:
   - типові команди, які розбираються в інших модулях, → «не входить у сценарій цього модуля, розбираємо в модулі N»
     (записи `reserved-*`, `"hidden": true` — не показуються в сайдбарі);
   - інші команди інструмента (`git …`) → «не входить у сценарій цього модуля»;
   - будь-яке інше введення → `fallback` профілю (`{input}`).
   Текст `not a registered command` учень не бачить ніколи.
5. **Узгодженість з уроком.** Завдання «Практика» в уроці виконується саме в цьому інструменті
   («зміни вже є» — якщо сценарій їх містить; імена — ті самі, що в профілі). Привітання уроку (`lessons.<key>.welcome`)
   каже, з чого почати; сайдбар «This lesson» — команди саме цього уроку.
6. **Мова.** Мова підказок і привітань — мова курсу; вивід інструмента (git) — як у реальності, англійською.
7. **Розмір.** Профіль генерується скриптом, якщо в нього багато варіантів; орієнтир — до ~0,5 МБ на чаптер.
8. **Перевірка перед імпортом.** Сценарії уроків проганяються через рушій 4wp-advanced-code (`find-command.js`)
   по кроках завдання; у виводі немає заготовок, що суперечать введенню.

## Наслідки
- 4wp-advanced-code: `fallback` профілю, `hidden` записи, `{name...}` — захоплення решти рядка,
  точний збіг команди спершу з урахуванням регістру (`-d` ≠ `-D`).
- LMS4WP `AdvancedCodeTerminal`: передає `fallback`, не показує `hidden` у сайдбарі.
- Нові інструменти (IDE тощо) — ті самі вимоги 1–8 у власному форматі.
